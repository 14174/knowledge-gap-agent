# 实验合同

## 冻结变量

`RunConfig` 的 `schema_version`、实验标识、变体、模型提供方/名称/版本、温度、步数、超时、重试、`prompt_hash`、工具集版本、数据集版本、`corpus_hash` 与 `random_seed` 均进入 `config_hash`，因为它们会改变可复现实验的输入、执行边界或随机性。

## Trace 约束

`TraceEvent` 必须有运行/任务标识、步骤、`agent`、事件类型、状态和配置哈希；其 `model_dump(mode="json")` 输出为 JSON 兼容的 Trace 表示，`usage` 包含 `input_tokens`、`output_tokens`、`context_tokens` 与计算字段 `total_tokens`。这不是配置哈希的规范化流程。失败状态必须提供 `error_type`，成功状态不得提供它。

## BenchmarkCase

六类为 `local_sufficient`（本地知识足够，不应研究）、`local_partial`（部分覆盖）、`local_missing`（缺失）、`outdated`（过时）、`conflict`（冲突）、`repeated_knowledge`（重复知识）。人工标注的意义是固定问题、所需声明、允许来源、答案要点与是否需要研究，作为评测真值。

当前候选集使用其中四类：12 个基础问题各派生 `local_sufficient`、`local_partial`、`outdated`、`conflict` 四个环境，共 48 条候选。固定语料、主张、环境三池、候选草稿、Reviewer 输入和复核记录均已落盘，并由确定性测试检查引用、互斥、缺失主张和模型输入白名单。

当前两轮独立模型复核的规范合并包含 48 条 `approve`：未修改的 40 条保留首轮原记录，修订的 8 条采用第二轮原记录。模型复核不能替代人工终审。12 条 `outdated` 和 12 条 `conflict` 共 24 条仍为人工 `pending`；其余 24 条为 `not_required`。因此当前只能称为候选数据，没有正式 freeze，也没有正式发布的数据集哈希。

## 指标

`TaskSuccess = 成功任务数 / 总任务数`；`Precision = TP / (TP + FP)`；`Recall = TP / (TP + FN)`；`F1 = 2PR / (P + R)`；`FalseSufficientRate = 被错误判为本地充分的任务数 / 实际需要研究的任务数`。结果留待真实实验后填写。
