# 首批四张卡片修订说明

## 这次修的是什么

问题不在搜索算法，而在评测题的证据：此前有些“冲突”只写在关系字段里，读正文却不能证明双方冲突。这样的题即使让程序通过校验，也不能可靠评估智能体。

本次修正正文，保存旧的退回意见，再对所有受影响的题重新复核。没有把模型复核通过写成人工批准。

## 四张卡片逐条看

| 卡片 | 原来的问题 | 修订后如何判断 |
| --- | --- | --- |
| 配置哈希：过时证据 | 旧规则禁止键排序，现行规则要求排序；这条原本就成立。但它与下一张共享问题和证据，必须一起更新审核目标。 | 本地旧规则已经失效；研究池提供现行排序规则。因此仍需要搜索。 |
| 配置哈希：冲突证据 | 原第二端要求数组排序，但研究池没有提供数组排序的裁决依据。 | 第一端禁止键排序，第二端要求键排序，二者直接冲突；现行规则用键排序否定第一端，再用 UTF-8 和拒绝非有限值否定第二端。 |
| 冻结容器：过时证据 | 原当前主张只反对自定义容器，没有明确说明应选哪种容器。 | 旧规则只允许普通列表并禁止元组；当前主张明确选择元组，两端正文形成直接对立。 |
| 冻结容器：冲突证据 | 当前主张没有明确选择元组，不能同时裁决两条“唯一允许的容器”规则。 | 两端分别只允许普通列表、自定义不可变列表子类；当前主张明确选择元组，并说明子类可被绕过和复制问题，能够分别裁决两端。 |

配置哈希问题现在只问“身份哈希前如何规范化、哪些配置变量改变身份”，不额外要求来源没有说明的摘要算法。容器问题仍要求解释子类不足、为何选元组、如何保持 JSON 数组输出；部分知识环境只给容器与数组兼容规则，仍缺少子类风险原因，因此依然确有知识缺口。

## 为什么重审了十四条

一条证据可能出现在多道题里，既可能是本题答案，也可能是其他题的干扰项。程序逐条比较修订前后的审核目标哈希，实际找到十四条变化；不是只重审四张卡片，也不是人为指定十四条。其余三十四条输入未变化，保留原有复核记录。

十四条重新通过了独立模型复核与另一代理的质量检查。这证明本轮数据修订通过了复核流程，尚不能证明智能体效果提升。

## 接下来由你审核什么

打开[完整人工终审清单](阶段一人工终审清单.md)，按“基础问题编号 → 类别”找到前两组的四张卡片，核对三件事：

1. 不看冲突关系字段，仅凭正文，是否真的互斥或过时？
2. 本地知识是否确实缺少问题要求的一部分，而不是仅换了一种说法？
3. 研究池是否直接补足缺口，并能逐端裁决冲突，而不借用排除池？

新清单仍有二十四条高风险候选待人工终审。可以继续逐批审核；旧目标上的退回意见只作为历史保留，不能批准修订后的新目标。

复核输入、输出、实际差集和验证记录见[实验记录](experiments.md)；构造规则见[候选基准构造说明](benchmark-construction.md)。
