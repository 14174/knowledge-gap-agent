# 知识存储与检索

实现入口为 `knowledge/store.py`，检索算法复用 `retrieval/bm25.py`。不接入特定知识产品，不新增向量服务，不用相关性分数直接判断充分性。

## 数据与调用

`KnowledgeEntry` 保存 `knowledge_id`、正文、引文元组、完整来源元组、正文摘要、来源运行和写入时间。SQLite 表为 `knowledge(id TEXT PRIMARY KEY, payload TEXT NOT NULL, verification TEXT NOT NULL)`；后两列分别保存条目和验证候选的 JSON。

`put_verified(candidate)` 先调用 `revalidate`，再按正文及排序去重的“来源、证据摘要”对计算稳定编号。参数化 `INSERT OR IGNORE` 保留首次记录；同一正文但出处关系不同，不应错误合并。`entries()` 按编号排序；关闭重开仍可读取凭据。

`search(query, top_k=4)` 从实际条目构建 BM25，并把命中编号关联回正文及分数；`KnowledgeHit.as_evidence()` 为运行模型保留全部来源。当前每次检索重建索引，适合本轮小库，不声称大规模索引性能。

```text
通过候选 → 重验 → 稳定身份 → SQLite
查询 → entries → BM25Index.build/search → KnowledgeHit → EvidenceView
```
