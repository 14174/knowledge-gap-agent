# 运行时与轨迹实施计划

目标：按对应设计建立真实可调用、可保存和可重放的最小循环。使用子代理逐项实现，主代理组织规格与质量审查。技术栈保持 Python、Pydantic、标准库 HTTP 与 pytest。

- [ ] 阅读既有配置/轨迹模型；先写 `tests/runtime/test_loop.py`，固定模型返回研究→作答，断言观察引用和停止原因；运行确认缺少模块的红灯。
- [ ] 实现 `runtime/models.py`、`model.py` 与 `loop.py`；新增非法动作、重复查询、步数上限、工具/网络超时和引用越界回归。模型使用 `complete(system, payload, *, max_tokens)`，网络响应用量来自真实服务，不模拟性能数据。
- [ ] 为 `tracing/store.py` 写失败测试：保存后原始记录、模型响应、工具观察可重验，任何内容篡改被拒绝，同路径不同内容拒绝覆盖；实现最小存储及无外部调用重放。
- [ ] 添加两个演示和运行时状态机文档，所有固定模型输出明确是工程演示。
- [ ] 运行 `uv run python -m pytest tests/runtime tests/tracing -q` 与两个演示；记录命令、结果和限制。
- [ ] 独立规格审查 → 修复 → 独立质量审查 → 修复；主代理集成验收后提交阶段快照。
