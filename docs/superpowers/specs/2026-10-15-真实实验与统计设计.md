# 真实实验与统计设计

## 范围和输入

完成冲刺 E0–E3、写回复用和候选技能离线实验。使用现有四十八条候选与固定语料，不修改标签。保存 `artifacts/experiments/<batch>/snapshot/` 的运行、标签、审计物理分离候选快照和原始文件摘要；元数据注明二十四条待真人终审，不借正式冻结批准接口。

主题 01–04 的十六条为开发集；05–12 的三十二条为独立评测集，三次重复。参数、提示词、评分规则和分集清单先落盘，再接触评测输出。论文式性能主张不超出该模型、候选语料与小样本范围。

## 模块边界

- `eval/dataset.py` 加载可信既有夹具，检查模型记录与当前目标匹配；构造运行侧 `TaskInput` 和注入式研究工具。主张编号、答案、类别与池编号只存在评测器，运行侧仅问题、正文、临时引用。可见池先用 BM25 排序取四块；研究工具在可见池与研究池并集检索，永不访问排除池，最多返回四块。引用映射单独保存供评分。
- `eval/runner.py` 编排变体、重复和单次知识库，不把标签传运行时。每条保存运行配置、真实调用响应、门禁判断、工具查询、实际引用映射及耗时；失败也是有效结果，不静默丢样本。每任务存储后才评分。
- `eval/grading.py` 独立模型裁判读取问题、答案要点、已完成回答与实际被引用证据，不提供变体、充分性预测或模型自评分。输出逐要点覆盖、是否出现关键错误、各引用是否支持回答、理由。任务成功要求所有必要要点覆盖、无关键错误、至少一条有效引用且所有引用合法。记录判题原始响应；格式失败记评分缺失，单列，不算运行成功。评分不能影响运行或写回库。
- `eval/metrics.py` 计算混淆矩阵、精确率、召回率、F1、错误充分率、任务成功、引用支持率、搜索/令牌/延迟和步骤，零分母输出 `null`；按基础主题聚合三次重复后进行一千次有放回主题簇自助采样，固定随机种子，报告 E2 相对 E1/E0 的配对差值区间。
- `eval/report.py` 只读取版本化实际产物计算 Markdown 与 JSON 总表，缺失数据明确报告；重算不调用模型、不改旧结果。
- `scripts/run_experiments.py` 显式 `--live` 才调用服务；支持按已存在逐任务记录恢复，但不同配置摘要拒绝混用，不把重放当新增重复。用全局调用预算限制真实请求，默认上限 1800 次（含所有裁判和重试），每次输出至多 1800 令牌。并发最多四，优先正确留档。先开发集冒烟，修复接口后冻结协议，再运行留出。

## 变体和消融

E0 不读取长期知识，模型先研究再作答；E1 使用初始本地知识，但仍采用固定先研究策略；E2 在 E1 上只增加充分性判断，足够且置信度至少 0.8 时跳过研究，否则研究。E3 与 E2 采用相同回答机制，回答后另行验证研究候选并写入隔离 SQLite。E3 主集不跨任务复用，因此主表分别报告其验证开销；复用收益仅在第二轮配对实验报告。

E0 与 E1 的研究工具、同题研究范围和检索参数相同。模型研究是否遵循策略由实际搜索记录核对，未遵循视为运行失败，不由评测器伪造搜索次数。充分性只根据问题和证据自行预测，分类性能是中间指标，同时报告任务结果与效率。所有输出保留失败，不能在观察结果后挑样本或修改阈值。

## 写回复用

对主题 05–12 的部分覆盖环境分别设置八组“第一轮原问题 → 第二轮不同表述的相关问题”，保留来源与改写审计。第一轮 E3 三次各自知识库，第二轮分别读取新增知识和无写回初始快照，使用同一充分性与回答流程。模型仅从本轮研究观察中提取可复用事实，不复制最终答案全文或标签。每组单独库，禁止不同主题写入造成污染。第二轮问题与原问题不可相同且不得添加答案性提示。

复用成功要求实际检索新增知识 ID 且答案引用它；报告检索命中率、实际引用复用率、质量和搜索下降。无写回搜索总数为零时下降率为 `null`，不制造百分比。

## 候选技能

仅根据开发主题真实失败或成功轨迹提炼一个候选，记录来源运行、步骤与适用条件，候选版本和主题 05–08 回归、09–12 目标集合先冻结。三次 E2 无技能结果作为配对基线，使用候选额外提示执行同题实验并独立评分。目标收益不负、回归率为零才 `validated`，否则原样拒绝；默认运行时不晋升候选。没有有益候选时报告未获得证据，不为了通过修改留出门槛。

## 指标和限制

评测器以 `(case_id, variant, repeat)` 为唯一运行键，模型内的内容派生 `task_id` 只作输入身份。尤其 E0 同题不同环境可能拥有相同输入摘要，绝不能据此覆盖不同评测运行；评分、恢复和技能配对都使用评测器键。该关联不进入模型载荷。

任务成功率分母固定为预注册全部运行，运行失败计失败；评分缺失同时单列，保守成功率将其计为未成功，并可另报已评分子集结果但不得代替主指标。配对区间要求预注册各主题、四环境、三重复结构完整；缺配对时区间标不可用，不筛选完整案例提高结果。主题采样始终同时携带四环境和三重复。

预算账本在每次真实 HTTP 尝试前原子预留并持久化；中断和超时仍消耗额度，恢复读取账本。模型、充分性、知识提取、验证、评分及重试均计入1800。固定优先级为主实验三次 → 评分 → 复用 → 技能，开发冒烟也计入；预算耗尽不再请求，报告预注册缺失情况。预算是费用控制上界，不保证任何实验必成功。

报告分别汇总运行端到端用量/延迟（含充分性、循环、提取和验证）与离线评分开销。原始记录按组件留存，未知用量不能当零；模型失败和重试开销不得遗漏。有服务用量但本地计时不完整时，保留已知值并标记缺失。

搜索“需要”真值读取候选 `need_research`，预测由真实研究调用或充分性决策得出；分别统计决策与执行，失败不得默认判为足够。搜索次数是实际工具次数，令牌使用服务响应，模型与工具延迟分别留档。服务若不返回价格，不估算金额。三次重复不是独立主题扩容，单模型裁判可能有系统偏差，答案引用存在与语义支持分开计数。人工终审后的标签或正文若变化，必须重新运行受影响实验，现有探索结果不能升级成正式结果。
