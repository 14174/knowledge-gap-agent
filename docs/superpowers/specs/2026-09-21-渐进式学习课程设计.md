# 渐进式学习课程设计

> 状态：设计已确认，等待书面审阅。本文定义教学材料的组织方式，不改变 Agent Runtime、实验变量或 10 天冲刺的功能边界。

## 1. 目标与受众

课程面向会使用 Python、调用过一次大模型接口，但没有独立实现过 Agent 的开发者。学习者不需要从智能体发展史或语言模型基础开始；课程直接进入状态机、工具调用、检索算法、Trace、评测和实验设计。

完成五个阶段后，学习者应能：

1. 根据 Trace 解释 Agent 每一步为什么发生，并定位一次失败；
2. 用伪代码表达 Runtime、检索、Gate 和回归检查的控制流；
3. 修改一个实验变量，保留其他控制变量，并解释指标变化；
4. 从早期代码快照逐步复现最终系统，而不是只运行最终 Demo；
5. 使用 AI 获取诊断和提示，同时保留独立推理过程。

课程不承担 Python、大模型接口和提示词基础教学，也不建设学习平台、自动判题网页或账号系统。

## 2. 组织方式

主分支保存最新实现，五个 Git 标签固定各阶段的可运行快照：

```text
learn-v0.1-eval-contract
learn-v0.2-react-runtime
learn-v0.3-knowledge-gap
learn-v0.4-knowledge-evolution
learn-v0.5-skill-gate
```

课程材料单独放入 `learning/`，避免与 `docs/` 下的架构设计、实验记录和结果报告混在一起。

```text
learning/
├── README.md
├── stage-01-eval-contract/
│   ├── GUIDE.md
│   ├── LAB.md
│   ├── EXERCISES.md
│   └── SOLUTIONS.md
├── stage-02-runtime/
├── stage-03-knowledge-gap/
├── stage-04-knowledge-evolution/
└── stage-05-skill-gate/
```

课程直接引用真实源码、测试、Demo 和 Trace，不复制一套教学版实现。代码修改后，维护者必须同步检查对应阶段文档；若新实现破坏旧标签，旧标签保持不变，只在主分支修正文档说明。

## 3. 学习闭环

每个阶段采用同一顺序：

```text
问题场景
→ 运行最小 Demo
→ 阅读数据结构、算法和公式
→ 修改一个变量或制造一次失败
→ 阅读 Trace
→ 完成简答与伪代码
→ AI 提示与评分
→ 运行阶段验收
→ 进入下一个 Git 标签
```

每个 Demo 必须输出输入、中间状态或 Trace、结果、指标或断言。只展示成功路径不算合格；每个阶段至少保留一个失败、拒绝或恢复案例。

## 4. 单元文件契约

### 4.1 `GUIDE.md`

单篇按 30–45 分钟阅读量控制，固定包含以下内容：

1. 一个真实失败案例；
2. 本阶段可以运行和观察的结果；
3. 模块的输入、输出、依赖和非职责；
4. 核心数据结构及字段生命周期；
5. 状态转移、算法、公式或阈值；
6. 真实代码入口、核心函数和测试路径；
7. 一条成功 Trace 与一条失败 Trace；
8. 当前版本的取舍和下一阶段将改变的部分；
9. 可直接执行的验收命令。

文档不大段复制源码。代码导航应精确到文件和函数，并说明学习者需要观察什么。

### 4.2 `LAB.md`

每个阶段有三个实验：

- 基础实验：跑通最小路径；
- 参数实验：只修改一个阈值、步数、检索参数或 Gate 条件；
- 故障实验：主动制造超时、空结果、重复动作、过期证据或回归 Skill。

学习者使用统一记录格式：

```text
实验假设：
修改变量：
控制变量：
预期现象：
实际结果：
Trace 位置：
结论：
```

参数实验若同时改变两个以上变量，实验不通过。实际结果与预期不同不算失败，但必须基于 Trace 解释差异。

### 4.3 `EXERCISES.md`

每阶段默认 8 题，预计用时 60–90 分钟：

| 题型 | 数量 | 评价目标 |
|---|---:|---|
| 简答题 | 3 | 模块边界、错误来源和变量控制 |
| 伪代码题 | 2 | 控制流、数据结构和边界处理 |
| Trace 分析题 | 1 | 从事件链定位失败步骤 |
| 实验设计题 | 1 | 对照组、指标、样本和控制变量 |
| 代码修改题 | 1 | 在真实代码中完成小范围改动 |

题目分为基础、应用和挑战三级。不考术语背诵。伪代码题必须给出输入、输出、约束和至少一个边界案例；代码修改题必须有测试或可执行断言。

### 4.4 `SOLUTIONS.md`

答案与题目分离。每题包含：

```text
提示：只指出下一步应检查的对象。
参考答案：给出一种满足约束的解法。
评分点：列出可独立计分的推理和边界条件。
常见错误：说明错误会如何反映在 Trace 或测试中。
```

简答题按证据和推理评分，不按关键词评分。伪代码允许不同控制流，只要满足接口、状态更新和失败处理约束。

## 5. AI 辅导契约

仓库提供统一提示词。学习者提交当前阶段文档、题目、自己的答案或代码以及相关 Trace。AI 按三轮工作：

1. 诊断：只指出最关键的推理缺口；
2. 提示：每轮提供一个方向、反例或待观察字段；
3. 评分：学习者修订后，按照 `SOLUTIONS.md` 的评分点逐项评价。

默认提示词：

```text
你是本项目的学习辅导员。

先判断我的答案缺少哪一个关键推理步骤，不要立即给出完整答案。
优先引用当前阶段文档、代码接口和 Trace。
每轮只给一个提示。
我提交修订答案后，再按评分点逐项评价。
如果答案与参考实现不同但满足约束，不得仅因写法不同扣分。
不要虚构没有运行过的测试结果。
```

AI 不应在第一轮读取答案后直接复述参考答案。学习者明确要求查看答案，或经过两轮提示仍无法推进时，才展开完整答案。评分必须指出对应评分点和证据，不能只给总分。

## 6. 五阶段课程地图

| 阶段 | 工程主题 | 算法与建模内容 | 代表练习 |
|---|---|---|---|
| 一 | 实验合同、配置哈希、数据集 | 分层抽样、混淆矩阵、配对实验、Bootstrap | 编写避免数据泄漏的任务分割伪代码 |
| 二 | ReAct Runtime、工具执行、Trace/Replay | 有限状态机、终止条件、重试、动作归一化 | 编写重复动作检测和错误恢复伪代码 |
| 三 | BM25、KnowledgeProvider、Sufficiency Gate | BM25、Claim 覆盖、三分类与阈值取舍 | 计算一次 BM25 排序并分析误判 |
| 四 | Evidence Verification、写回与复用 | Claim-Evidence 对齐、冲突检测、去重、复用率 | 设计证据 Gate 和知识版本更新伪代码 |
| 五 | Candidate Skill、目标集和回归集 | 适用范围、配对增益、回归率、Promotion Gate | 判断候选 Skill 是否允许发布 |

每个阶段结束时，学习者应提交实验记录、练习答案和一段失败分析。课程不要求所有人得到完全相同的模型输出，但要求控制变量、Trace 和结论之间一致。

## 7. 质量门禁

创建阶段标签前必须满足：

- 阶段 Demo 能在干净环境运行；
- 文档中的路径、命令和输出与标签一致；
- 至少包含一条成功路径和一条失败路径；
- 所有练习都能从本阶段材料推导；
- 题号、答案和评分点一一对应；
- 参考答案不依赖后续阶段知识；
- 阶段测试通过；
- `CHANGELOG` 说明相对上一阶段新增的行为；
- 标签对应提交没有未提交文件。

文档校验脚本负责检查目录、必要文件、内部链接、题号和答案编号。持续集成运行阶段核心 Demo 和测试。模型输出不能做完全字符串匹配；测试应验证 schema、状态转换、指标计算和固定夹具上的行为。

## 8. 与 10 天冲刺的关系

学习材料跟随实现生成，不另开一条课程开发线：

| 冲刺阶段 | 同步形成的学习阶段 |
|---|---|
| 第 1–2 天：实验合同与数据底座 | 阶段一 |
| 第 3–4 天：Runtime 与 E0 | 阶段二 |
| 第 5–6 天：知识检索与充分性 Gate | 阶段三 |
| 第 7–8 天：证据写回与知识复用 | 阶段四 |
| 第 9–10 天：候选技能与总报告 | 阶段五 |

每天先保证代码、测试和实验记录可信，再补齐对应的学习说明与练习。若当天实现没有通过阶段验收，不创建学习标签，也不编写假定实现已经成功的参考答案。

## 9. 验收标准

设计落地后应满足：

1. 五个阶段都具备 Guide、Lab、Exercises 和 Solutions；
2. 五个标签都能检出对应代码快照并运行阶段 Demo；
3. 每阶段有 8 道题，至少包含 2 道伪代码题；
4. AI 辅导模板能按提示、修订、评分三轮使用；
5. 文档校验能发现缺文件、坏链接和题号不匹配；
6. 课程引用的指标、实验结果和 Trace 与 `docs/` 中的真实产物一致。
