# 模块架构

配置、语料、检索与基准门禁沿用 `cc0dcbe`。运行时与轨迹实现见 `0a54ac7`，知识闭环见 `c04d715`，隔离评测见 `2fba428`；真实批次执行进度以待办和实验报告为准。

后置完整性与资源修订为 `ccf7f68`，不修改原实验策略或原始结果；真实观测仍绑定 `2fba428` 协议。最终机器报告在修订前后及目录迁移下相同。

```text
评测驱动器（独占标签及环境池配置）
  ├─ 问题与可见证据 → runtime → 模型适配器
  │                       ├─ 研究工具（仅允许的证据池）
  │                       └─ tracing（调用、观察、重放）
  ├─ knowledge → SQLite、既有 BM25、充分性与写回验证
  ├─ 完成的回答 → 独立评分器 → 配对统计与报告
  └─ 开发轨迹 → skills候选 → 目标/回归评测 → validated或rejected
```

稳定数据契约不承担运行控制。模型只接收问题与允许证据，不接收答案、类别或主张图。运行结果先落盘再评分；评分不能反向影响当前运行或知识库。主实验每任务独立知识初始状态，只有复用实验允许跨轮写入。

人审批准是正式数据冻结的外部事实，代理自动审查不能代替。探索实验通过专用候选快照与明确状态支持先完成开发，正式冻结器不改写。

## 持久化与接口

运行时入口为 `run_task(TaskInput, RunConfig, ModelClient, research)`；模型适配器读取环境鉴权，响应、实际模型与用量进入轨迹，鉴权和接口地址不进入产物。`save_run/replay_run` 保存完整动作循环并离线重走状态机；外层充分性、提取、验证和评分由评测调用记录另存，不在循环重放中再次执行。不提供逐步检查点恢复。

`SQLiteKnowledgeProvider` 负责知识持久化与 BM25 检索。`knowledge` 表保存正文、来源、证据、验证凭据和内容身份；只有 `put_verified` 接收经重新校验的通过候选。多来源证据转换保留全部来源，身份按来源与证据摘要对计算。

评测目录包含 `protocol.json`、物理分离的 `snapshot/runtime`、`snapshot/labels`、`snapshot/audit`、逐运行结果与调用、技能清单，以及 `calls.sqlite`。账本 `attempts` 表在每次真实 HTTP 尝试前事务预留，失败和重试都计数；缺失用量保持未知。结果与评分按运行内容摘要绑定，协议固定数据、提示词与源码摘要；同目录恢复不得更改条件。

当前研究工具仅在固定环境的可见池与研究池并集中检索，不访问排除池，不执行开放网页搜索。模型调用是真实远端调用，研究材料是固定语料，两者不能混称“实时联网研究”。技能通过只标为离线验证，不自动发布、晋升或回退。
