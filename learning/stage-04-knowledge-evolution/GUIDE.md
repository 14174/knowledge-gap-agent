# 阶段四：证据验证、写回与不同问题复用

本阶段已展开，沿真实 `verify_candidate → put_verified → search → as_evidence` 调用链学习。先完成阶段三，知道检索命中和知识足够的区别。

## 两个真实审查发现

第一版知识编号分别汇总来源集合与证据摘要集合。两份证据互换所属来源后，这两个集合不变，知识编号也不变，导致不同出处被错误去重。修复使用“来源、证据摘要”成对摘要。

另一个问题出现在复用转换：多来源正文只保留第一个来源，就可能让仅准入该来源的后续验证通过。修复要求派生证据保留完整来源集合，并逐个检查准入。这两例都说明：正文没变，并不意味着证据关系没变。

## 运行与源码顺序

```powershell
uv run python demo/07_evidence_gate.py
uv run python demo/08_round_trip_reuse.py
uv run python -m pytest tests/knowledge -q
```

两个演示使用固定模型响应，展示拒绝、通过和实际知识编号被引用的工程路径；真实复用率来自后续实验。

1. [验证](../../src/knowledge_gap_agent/knowledge/verification.py)：`validate_target` 检查空文、引用、来源与时间；`verify_candidate` 发起单独语义审核，返回通过候选或带原因的拒绝。
2. 同文件的 `revalidate`：入库前重算目标和凭据，重新解析模型审核结果，拒绝修改正文后复用旧批准。
3. [存储](../../src/knowledge_gap_agent/knowledge/store.py)：`put_verified` 建立稳定知识编号，参数化写入 SQLite；重复内容与实际出处保留首次记录。
4. `search` 复用已有 BM25；`as_evidence` 将命中转成运行模型可见证据，保留完整来源约束。

数据路径是研究观察 → 提取一条可复用事实 → 独立验证 → 写入 → 第二个不同问题检索 → 回答引用。候选正文从真实研究观察提取，不从标签或最终标准答案复制。

## 两层门禁

确定性门禁检查“引用是否存在、是否重复、来源是否准入、正文摘要是否一致”。这些检查可以精确复现，但不能证明自然语言支持关系。

语义门禁通过单独模型请求检查每条候选主张是否由引用支持，是否有矛盾、时效风险或未经支持的扩展。通过且置信度至少0.8才产生 `VerifiedCandidate`；原始请求、响应、拒绝原因和用量保留。

```text
目标摘要 = Hash(候选正文、按序引文、引文正文摘要、来源、来源运行)
入库条件 = 重算目标相同 ∧ 凭据相同 ∧ 审核正文一致
           ∧ accepted为真 ∧ confidence≥0.8
稳定知识身份 = Hash(正文、排序去重的来源与证据摘要对)
```

目标摘要保留本次审计上下文；稳定知识身份不依赖临时引用编号或单次运行，因此同一事实、同一出处可去重。它们解决不同问题，不能共用一个字段。

## 成功与拒绝记录

成功路径：候选只复述证据支持的内容，来源准入，独立模型通过；数据库保存验证凭据，关闭重开仍可检索到同一知识编号。

拒绝路径：候选有一条引用不在观察中，在模型调用前就拒绝并保留目标；或引用存在，但模型判断候选扩展了证据未说明的结论，语义门禁拒绝。失败不是空成功条目，不能进入活动知识库。

没有时效元数据时，模型只能依据正文判断风险，不能证明事实永不过期。验证凭据是审计绑定，不是抵抗恶意程序重签名的授权系统。

## 如何证明实际复用

```text
检索命中率 = 检索到新增知识的第二轮任务数 / 可复用任务数
实际引用复用率 = 回答引用新增知识的任务数 / 可复用任务数
搜索减少率 = 1 - 有写回组搜索次数 / 无写回组搜索次数
```

零分母不给下降百分比。两个问题文字必须不同；每组知识库隔离，只允许该组第一轮新增条目流入第二轮。同题四环境共享可写库会泄漏先前任务的证据，不能用来证明门禁有效。

搜索少了还要看答案质量。引用一个新增编号只能证明发生使用，是否支持结论要由隔离评分继续检查。

固定教程第八章的持久记忆与检索分层在此落为数据库和提供器边界，第十二章的人工验证提醒我们保留模型审核局限。学完后，用一条多来源知识重走验证、入库、转换和再次验证，解释来源为什么不能在中途缩成一个。
