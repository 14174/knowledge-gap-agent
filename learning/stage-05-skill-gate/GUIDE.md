## 一个不应被发布的候选

候选在目标任务上平均提高了0.2，但让回归集中的任务下降，是否应该采用？演示09会拒绝这个候选；另一个不退化候选可标为 `validated`，仍不自动改变默认策略。这是固定数据门禁演示，真实收益要由实际配对运行得到。

1. [候选门禁](../../src/knowledge_gap_agent/skills/gate.py)：`CandidateSkill` 绑定适用范围、步骤、来源轨迹、开发任务和版本；`freeze_evaluation` 保存候选与分集摘要；`evaluate_skill` 重读磁盘清单再比较配对。
2. [真实运行编排](../../src/knowledge_gap_agent/eval/runner.py)：保存原始运行、配置和调用，完成后才评分。

```text
开发轨迹 → 候选步骤与版本
 → 提前冻结候选及目标/回归任务
 → 同题无技能/有候选真实运行
 → 隔离评分 → 配对门禁 → validated或rejected
 → 原始产物离线重算 → 有边界的简历证据
```

## 为什么先冻结

开发主题与目标、回归主题没有交叉。同题四环境必须在同一分割；看到留出答案后再改候选，就已使用该集合参与迭代，另起文件也不能恢复其独立性。

清单固定候选内容摘要、开发任务、目标任务、回归任务和阈值。配对记录必须逐题对应，集合非空、唯一、互斥，分数有限且在零到一之间，版本摘要一致。内存里传入一份看似合法的清单还不够，门禁会重读真实冻结文件。

```text
目标收益 = mean(候选得分 - 基线得分)
回归率 = 回归集得分下降任务数 / 回归任务数
默认通过 = 目标收益≥0 且 回归率≤0
```

成本差也保留，但没有可信单价时使用真实令牌或明确单位，不自行换算金额。候选通过门禁仍是离线结果，默认运行策略保持显式版本控制。

## 三次重复怎么统计

当前源数据有十二主题，每题四环境。开发使用主题01–04，留出使用05–12，共三十二条环境任务；每个变体重复三次。它们不是九十六个独立主题。

对每个主题，先保留其四环境和三重复配对，再算主题平均差；有放回抽取八个主题均值，一千次得到区间。若缺任何预注册配对，区间标不可用，不能删掉失败题后宣称完整结果。区间跨零时不称为稳定提升。

任务成功率分母固定为全部预注册运行。运行失败算未成功，评分缺失单列且保守主指标不当成功。搜索、总运行令牌与延迟包括充分性、循环、提取和验证；离线裁判开销另列。服务失败已消耗请求预算，即使没有返回用量也不能当零成本。

## 从产物到表述

效果表必须回链到批次协议、配置摘要、原始运行、裁判响应和统计代码。测试通过数量证明工程回归覆盖，不能证明模型能力；固定响应演示也不能产生任务成功率。

本轮候选数据尚有二十四条真人终审待完成。探索结果可以供最终审阅和复跑，简历效果表述应保留“固定候选集、单模型、三次重复”的范围，待用户确认后使用。不能把未观察的生产延迟、费用、用户规模或跨模型效果写进简历。

固定教程第十二章强调问答与工具调用应使用不同评估标准，本项目分别记录任务完成、研究决策、引用支持、实际复用和成本。学完后，用一个候选失败例说明：目标平均变好为什么仍可能被门禁拒绝？
