# 渐进式学习

课程面向能阅读 Python、希望从真实代码理解实验契约并逐步实现 Runtime 的学习者。五个阶段依次是评测契约、ReAct Runtime、知识缺口、知识演化和 Skill Gate；阶段标签计划为 `learn-v0.1-eval-contract` 至 `learn-v0.5-skill-gate`。标签只有在对应代码、材料和人工门禁全部验收后才创建。

## 阶段入口

- 阶段一：[评测契约、语料与候选基准](stage-01-eval-contract/GUIDE.md)
  - [实验](stage-01-eval-contract/LAB.md)
  - [练习](stage-01-eval-contract/EXERCISES.md)

- 阶段二至五：随对应实现完成后补齐，不从未来设计反推虚构结果。

阶段一从两个本地 Demo 开始，覆盖稳定哈希、Markdown 行级切块、BM25 手算、知识环境、标签泄漏、独立复核和人工升级。当前材料基于候选数据；人工终审和正式冻结尚未完成。

## AI 三轮辅导

先完成一版答案或代码，并附上相关题目、当前阶段文档、实际输出或 Trace。三轮分别使用下面的提示词。每轮都保留自己的修订内容，不让 AI 直接替代推理。

### 第一轮：诊断

```text
你是本项目的学习辅导员。阅读我附上的阶段文档、题目、答案或代码，以及真实输出。
只指出最关键的一个推理缺口，不要给出完整答案，也不要同时列出多个方向。
优先引用当前阶段的字段、函数、公式或 Trace 位置。
不要虚构没有运行过的测试结果。
```

收到诊断后，先自行修订一次。如果诊断涉及输出，回到对应 Demo 或测试复现。

### 第二轮：提示

```text
这是我根据第一轮诊断修订后的答案。
请只给一个下一步提示，可以是一个反例、一个待观察字段或一条需要核对的边界。
不要展开 SOLUTIONS.md 的完整参考答案。
如果我的写法不同但满足接口、状态更新和失败处理约束，请保留这种写法。
不要虚构没有运行过的测试结果。
```

第二轮仍无法推进时，可以先查看题目对应的“提示”。只有明确需要时，再展开完整参考答案。

### 第三轮：评分

```text
这是我的最终修订答案，以及我实际运行的命令和输出。
请依据当前阶段 SOLUTIONS.md 中对应题目的评分点逐项评价。
每个得分或扣分都要指出答案中的证据；不要只给总分。
如果答案与参考实现不同但满足约束，不得仅因写法不同扣分。
不要把未运行的测试写成通过，也不要虚构没有运行过的测试结果。
```

评分后，把仍未满足的评分点转成一次最小复练。课程不要求模型输出逐字一致，但要求控制变量、代码行为、Trace 和结论彼此一致。
